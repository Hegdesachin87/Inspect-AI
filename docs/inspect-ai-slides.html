Step 3 · Solver and shell tool

Let the model inspect, edit, and check

solver=[
    system_message(
        "You are fixing a Python function. Edit the actual file, not just "
        "your final reply. Work in /workspace and check your repair."
    ),
    use_tools(bash(timeout=30, sandbox="default")),
    generate(),
]

generate() runs the conversation and tool-call loop.

Each shell call has a 30-second timeout. This task allows at most six model turns.

Step 4 · Docker sandbox

Keep repair and grading separate

Agent: default

Receives the broken file.

The model's bash tool runs here.

No fixed grading tests are supplied here.

Grader: grader

Receives the final source after the agent finishes.

Runs our fixed tests.

The model's shell tool cannot access it.

Pinned Python image. Separate temporary filesystems. No network, host mounts, or API keys in either container.

This is a cooperative repair exercise, not a hardened anti-cheating benchmark.

Step 4 · Switch to the live terminal

Run the evaluation

RUN="tutorial/repair-logs/demo-$(date +%Y%m%d-%H%M%S)"

OPENAI_API_KEY="$DEEPSEEK_API_KEY" inspect eval tutorial/repair.py \
  --model openai/deepseek-flash \
  --model-base-url https://api.deepseek.com \
  --log-dir "$RUN"

The API request goes to DeepSeek. The shell work runs in Docker.

Environment and Docker setup happen before the talk. This command makes real paid model requests. A successful outcome is not guaranteed.

Step 5 · Fixed-test scoring

Test the saved file, not the claim

  • Mixed even and odd values.
  • Empty input.
  • All-odd input.
  • Negative integers and zero.
  • Input list stays unchanged.

No LLM judge

python -B -m unittest -v fixed_tests

All tests pass → sample score 1.

Any test fails → sample score 0.

There is one sample and five tests. Accuracy 1.0 means that one repair passed every fixed test.
