# Approval experiment

**The eval that stops and asks** — [experiment 2](../../docs/small-inspect-experiments.md)
of the small-experiments guide, packaged to run from its own folder.

An agent demonstrates bash and python commands inside a Docker sandbox.
Two custom allowlist approvers auto-approve the safe ones (`ls`, `echo`, `cat`,
`print`, `math`); everything else escalates. In the interactive demo the
escalation lands at *your* terminal, mid-run; in the recorded run an `auto`
tier rejects it so the whole decision chain is captured without a TTY.

| Policy file | Escalation tier | Use |
| --- | --- | --- |
| `approval.yaml` | `human` — prompts you | the live demo (`./run.sh`) |
| `approval-record.yaml` | `auto` with `decision: reject` | unattended recording (`./run.sh --record`) |

## Run

```bash
export DEEPSEEK_API_KEY=...
./run.sh            # interactive: approve/reject rm and shutil.rmtree yourself
./run.sh --record   # unattended: record the full decision chain
.venv-tutorial/bin/python summarize.py logs/<newest>.eval
inspect view --log-dir logs --port 7575
```

Docker required (the repo's Colima profile `inspect-tutorial` is used if no
daemon is reachable). Cost: a handful of agent-loop calls — cents.

## Files

- `task.py` — the official Inspect approval example task + its two custom
  `@approver`s (`bash_allowlist`, `python_allowlist`), copied from the
  reference snapshot (see file header).
- `approval.yaml` / `approval-record.yaml` — the two policies.
- `run.sh` — both modes, provider-parameterized (MODEL/BASE_URL/KEY_VAR).
- `summarize.py` — prints every tool call with its approval chain and reason.
- `approval-demo.pptx` — slide deck explaining the experiment
  (generated by `make_slides.py` from `results.json`).
- `logs/` — the recorded run.

## Recorded result (2026-10-25)

`deepseek-flash` via DeepSeek, `--message-limit 30`, auto-reject recording
policy. Full chain per call in the log; `summarize.py` prints it.

- 26 tool-call attempts: **8 approved** (all allowlisted: `ls`, `echo`,
  `print`, `math.factorial`), **18 rejected** (`touch`, `mkdir`, `cp`, `ln`,
  `rm --help`, every `import os`/`shutil`/`tempfile` variant, and dangerous
  characters like `&&` and `>` rejected outright by the allowlist).
- The agent adapted constantly — after `touch` was rejected it tried `echo x >
  file` (rejected for `>`), then `python open(...)` (escalated) — a live map
  of an agent probing a policy boundary.
- In the recorded policy even `submit` is rejected (nothing allowlists it, so
  the auto tier rejects it); the agent ends at the message limit instead of
  finishing. In the interactive demo, approving the final `submit` is exactly
  the judgment a human adds. One observed quirk: one `submit` call was handled
  by `python_allowlist` and rejected as invalid Python — approver binding for
  that call is unexpected and unexplained; the raw events are in the log.

## Why the first recording attempt stalled (2026-10-25)

The official example's `react()` sets **no message limit**. Sample 1 finished
because that model run gave up and submitted; sample 2 retried rejected calls
for 69 minutes — 2,868 messages, 1,433 turns, 112.2M tokens (mostly cache
reads) — with no bound to stop it. `run.sh` now passes
`--message-limit 30` (override with `MESSAGE_LIMIT=`), which is itself the
lesson the tutorial teaches: limits are part of eval design.
